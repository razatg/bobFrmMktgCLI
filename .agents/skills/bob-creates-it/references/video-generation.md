# Image-to-video generation

Use this adapter after agreeing a video concept, source, scope and review criteria. It creates review-only account-scoped videos; it does not publish a Google Ads asset.

## Storyboard first

Create one `creative-runs/<run-id>/index.md` storyboard artifact before generation. It is the single editable planning and review surface for the run. Include narrative sections, pictorial panels, exact required copy, visual reference roles, dialogue and voice assignment, SFX, music direction, output plan and status. Do not create a new artifact for each storyboard revision.

Before prompt approval, review the saved board for what appears in each panel, the sequence and useful time guidance, dialogue and scene sound, and whether music or a jingle is wanted. A silent beat, untimed transition, or no jingle is valid only when the user explicitly accepts that omission. If timing, sound, or music guidance is missing, revise the same board using already agreed direction and present it for approval, or list only explicitly accepted gaps in the prompt brief's `accepted_omissions` (`timing`, `sfx`, `music`). General storyboard approval is not an omission waiver. Do not fill gaps with invented defaults or impose an equal-length beat grid.

Narrative sections follow the scene, not an arbitrary time grid. Mark only high-risk actions as `high`: moving vehicles, rapid interaction, complex hand contact, multiple changing subjects, or any action whose failure would invalidate the ad. The current adapter makes one continuous Omni scene, so mark these beats for close review. If a beat cannot be expressed or verified within one scene, revise the storyboard before approval rather than claiming it is a separate controlled clip.

Make the panels low-fidelity only when the source itself is enough to agree action; otherwise make high-fidelity, clean panels from the approved source. Each scene panel states the visual, camera, speaker, exact dialogue and voice. Include a final-card panel only when the concept calls for one. Present the board and wait for approval in chat. Then run `./bob video-create --brief <private brief> --run-id <existing run ID>` with a small brief such as `{"stage":"prompt","confirmed":true,"video_prompt":"One continuous scene with the approved dialogue."}`. The run ID comes from the existing storyboard artifact; the saved run supplies its scene images, panels, sound, copy, duration and ratio. The command updates the same `index.md`, not a separate prompt page. In chat, show the exact printed Omni text input as unfenced text, including its image-role markers, and copy the command's `[[artifact:wiki/.../index.md|...]]` marker exactly. The artifact keeps the full `{ "type": "text", "text": "..." }` object for verification. If asked to see the prompt again, use that same run page and marker. Wait for separate approval before running `stage: master` with the displayed prompt hash. Do not paraphrase or rewrite the text value. The command snapshots the approved brief. A later artifact edit cannot alter an already approved or in-flight generation.

If the user asks for the exact Gemini prompt after this stage, read the `text` value under “Omni text input for approval” in that run's `index.md` and paste it verbatim as unfenced chat text with the same artifact link. Omni is the Gemini video model used by this adapter; do not say there is no Gemini prompt or substitute a summary. If the prompt stage has not run, say the exact input is not compiled yet and complete the approved prompt stage first.

Each paid provider result is a durable run checkpoint: approved pictorial panels, raw video with its Omni interaction ID, then any explicitly requested separate music. If deterministic finishing or review fails, retry the same confirmed brief and run ID. Bob validates and reuses matching checkpoints instead of calling a provider again. Changing the approved visual or native audio prompt needs a new video candidate. Changes to deterministic finishing can reuse the raw video.

## Master and adaptation

The first executable route creates one fixed-duration `9:16` master. Its duration is declared by the selected allowlisted model in the creative catalog; it is not a Gemini request parameter. Give Omni every approved clean scene image: the first as `<FIRST_FRAME>`, the others as `<IMAGE_REF_N>`. Declare image roles at the start of the prompt, then name each image beside the scene it guides. Put a scene's SFX in that panel's optional `sfx` field; reserve top-level `sfx` for shared sound direction. Carry approved time guidance in panel `timing`, any jingle timing in `music.timing`, and a finishing card's start in `end_card.start_seconds`. These are pacing guidance, not hard cuts or Gemini duration parameters. Keep `video_prompt` to the concise overall direction; do not paste the full storyboard into it. The compiler adds the approved scenes, sound, timing, and finishing note to the same prompt. Keep exact supplied graphic assets for finishing when the storyboard assigns them that role. If a final product window is added in finishing, the Omni text input must describe only the scene before it; do not tell Omni to render or preserve that final frame. Omni produces native scene audio. Validate the raw video before finishing. Apply a final card only if the storyboard specifies one, at its approved start time; preserve the native audio through that card. If an exact logo is required but no approved logo file is available, stop before generation; never recreate the logo with AI.

After the master passes visual review and the user explicitly approves it, create a `16:9` FFmpeg adaptation. It retains the intact portrait video over an extended background; it never stretches pixels. If that arrangement is creatively weak, stop and propose a separate ratio-specific AI master instead of calling a crop successful.

## Sound

Specify SFX, dialogue, and music separately in the storyboard. Dialogue belongs to the named visible character and is generated natively with the scene. Omni generates the default soundtrack, including a jingle when approved. Natural-language time guidance may be included; it is not frame-accurate. Use Lyria only when the approved brief explicitly selects `music.provider: lyria`. Deterministic finishing applies only storyboard-specified graphics and preserves audio through the full master. Omni's saved interaction ID can be used for suitable visual edits; voice editing is unsupported, so a changed spoken line or vocal jingle requires a new generated candidate.

If a video or music provider returns a policy block, preserve every completed checkpoint and relay the returned policy message plainly. Do not guess at a safe rewrite, silently remove sound, change providers, or retry variants. Ask the user for a revised direction for the blocked stage and wait for approval. A separate Lyria music revision retries music and finishing only; a change to native Omni music or dialogue needs a new video candidate.

## Review

Before presentation, inspect every pending output using exactly these checks: `storyboard_fidelity`, `temporal_coherence`, `brand_fidelity`, `copy_accuracy`, `composition`, `audio_fit`, and `visual_integrity`. Watch the full video and listen to the full audio. Record `audio_listened: true` and brief `audio_notes` in each master review. Check the visible speaker against the assigned voice and line, the story and product role, the approved soundtrack, and any exact graphics or final card required by this storyboard.

Technical validation establishes duration, aspect ratio, streams and file integrity. It does not establish visual quality. A failed check needs a concise issue and must not be shown as passed. Present the single run artifact only after all pending outputs have a completed review.
